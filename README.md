# 在线抠图 · 纯前端（通用 / 人像）

一个完全跑在浏览器里的 AI 抠图工具，无需后端、无需 API Key、图片不出本地。

- **高清通用** 与 **快速人像** 两种模式
- 抠图后**更换背景**：透明 / 白 / 红 / 灰 / 蓝（切换背景无需重新抠图）
- 一键**下载 PNG**
- **通用模式**：[`@imgly/background-removal`](https://github.com/imgly/background-removal-js)（ONNX Runtime Web + WASM）
- **人像模式**：[MediaPipe Selfie Segmentation](https://developers.google.com/mediapipe)（轻量、头发边缘更干净）
- 两个库均通过 CDN **动态按需加载**，初始页面不加载任何模型

## 目录结构

本项目采用「拆分免构建」结构（B 方案），CSS 与 JS 从 HTML 中抽出、分层存放：

```
cutout/
├── index.html   # 页面结构，引入下面的样式与脚本
├── style.css    # 全部样式（配色、布局、进度条、按钮等）
├── app.js       # 全部逻辑（上传 / 模式 / 背景 / 抠图 / 进度 / 下载），ES Module
└── README.md    # 本说明
```

> 抠图库（`@imgly` 与 `MediaPipe`）通过 `app.js` 里的动态 `import()` 从外部 CDN
> 以浏览器原生 ES Module 方式**按需加载**，**无需打包、无需 Node 构建**。

## 技术方案

本工具属于「纯前端 AI 抠图」：所有 AI 推理都在访客浏览器内完成，**没有后端服务器、没有 API Key、图片不上传任何服务器**。核心由两个抠图引擎分治，按所选模式动态加载。

### 整体架构

- 页面（`index.html` + `style.css` + `app.js`）是纯静态文件，托管在 GitHub Pages。
- 抠图模型不打包进仓库。用户点击「开始抠图」时，由 `app.js` 通过浏览器原生 ES Module 的 `import()` **按需**从 CDN 拉取，用完后由浏览器本地缓存。
- 两个引擎都输出「透明背景 PNG 的 `Blob`」，统一交给合成模块 `reComposite()` 换背景色并生成下载链接——因此**换背景无需重新抠图**。

### 通用模式：`@imgly/background-removal`

| 项目 | 说明 |
|------|------|
| 推理引擎 | [ONNX Runtime Web](https://onnxruntime.ai/)，在浏览器内以 **WASM**（CPU 指令子集）运行神经网络推理 |
| 模型 | **ISNet**（U²-Net 类显著性目标检测），主体分割并带 alpha matting |
| 擅长 | 通用主体（人物、商品、宠物、景物），毛发/半透明边缘更自然 |
| 体积 | 首次使用下载引擎 + 模型（wasm 运行时、模型结构、权重，合计约 40MB），之后浏览器 IndexedDB 缓存 |

### 人像模式：MediaPipe Selfie Segmentation

| 项目 | 说明 |
|------|------|
| 推理引擎 | Google [MediaPipe Tasks Vision](https://developers.google.com/mediapipe)，自带加速运行时 |
| 模型 | `selfie_segmenter`（轻量 TFLite，几百 KB–几 MB），专为「人物前景/背景分离」设计 |
| 擅长 | 人物头发、肩膀边缘比通用模型更干净；**只识别人**，非人物主体请切回通用模式 |
| 加速 | 优先 **GPU（WebGL）** delegate；老设备 / Safari 不支持时自动降级到 **CPU** |

MediaPipe 输出 `categoryMask`：每个像素标注 `0=背景 / 1=前景`。`app.js` 把这张低分辨率 mask 映射到原图尺寸，写入 PNG 的 **alpha 通道**，得到透明图。

### 技术取舍

- **为什么纯前端可行**：推理在访客设备完成，不占站长服务器算力、零带宽成本，复用成熟开源模型即可，无需自研或训练。
- **代价**：首次需下载模型（已缓存则很快）；处理速度受用户本机 CPU/GPU 性能影响，老旧设备稍慢。
- **隐私**：图片全程在本地浏览器内存 / Canvas 处理，不上传任何服务器（仅有模型文件来自 CDN）。

## 功能介绍

页面自上而下分为四块：**上传区 → 参数区（模式 + 背景）→ 操作与进度 → 结果区**。

### ① 上传区（拖拽框）

- **点击框内区域** → 弹出系统文件选择（仅允许图片）。
- **拖拽图片入框** → 自动读取（拖拽时框会高亮）。
- **Ctrl / ⌘ + V 粘贴截图** → 任意位置粘贴即作为待处理图片。
- 选中后「开始抠图」按钮由禁用变可用；原图会显示在结果区「原图」卡片。

### ② 模式选择（卡片按钮）

| 选项 | 作用 |
|------|------|
| **高清通用**（默认选中） | 适合大多数主体：人物、商品、宠物、景物；全精度模型，边缘保真度最高 |
| **快速人像** | 针对人物优化的轻量快速路径；**仅识别人**，非人物主体请用高清通用 |

切换模式只改变选择，**不会自动抠图**；切换后清掉上一次的旧成品，避免显示错模式的图。

### ③ 背景选择（色板按钮，9 色）

| 选项 | 效果 |
|------|------|
| **透明**（默认） | 标准黑白马赛克纹理，保留 PNG 透明背景 |
| **白 / 黑 / 红 / 蓝 / 绿 / 黄** | 用对应纯色填充背景（蓝色为标准蓝 `#2878F0`） |
| **渐变** | 四色线性渐变填充 |
| **自定义** | 点击打开系统取色器，选任意颜色填充（色块实时显示所选色） |

切换背景**无需重新抠图**——直接在原透明结果上重绘背景，瞬时完成。

### ④ 开始抠图（主按钮）

- 点击后按当前模式调用对应引擎。
- **未选图片时按钮禁用**（浅金色不可点）。

### ⑤ 进度条

- 与「开始抠图」按钮**等宽**。
- 提示文案**固定居中在进度条下方**，随阶段变化：

  | 阶段 | 文案 |
  |------|------|
  | 准备 | 正在准备模型… / 正在加载人像模型… |
  | 下载模型 | 正在加载模型•第 N 个文件•X% |
  | 推理静默期 | 正在抠图… |
  | 完成 | 处理完成（随后整块消失） |

- 进度条**无浮动箭头指针**，文案固定居中在进度条下方。

### ⑥ 结果区与下载

- 抠图成功后**左右双栏对比**：左「原图」、右「抠图结果」（带黑白马赛克底）。
- 结果卡片右上角悬浮**圆形下载按钮**（灰色），点击下载当前（含所选背景）的 PNG 文件，默认文件名 `cutout.png`。

### ⑦ 页脚

- 显示当前版本号（如「版本 1.4.1」），用于确认线上是否为最新。
- 隐私声明：图片全程在浏览器本地处理，不会上传到任何服务器。

### 版本历史

- **v1.4.0**：UI 大版本重构——香槟金主题、5px 统一圆角、密集虚线边框、独立开口云朵上传图标；参数区双栏（抠图模式卡片 + 9 色背景板，含渐变/自定义取色）；结果区改为原图/抠图结果左右双栏对比，下载改为悬浮按钮；移除进度条浮动箭头，文案改为「正在加载模型•第 N 个文件•X%」；隐私声明更新。
- **v1.3.5**：模式按钮文案改为「高清通用 / 快速人像」，准确传达通用=质量优先(全精度 isnet)、人像=速度优先(MediaPipe 轻量)的定位区别。
- **v1.3.4**：人像模式由硬二值（0/1→255/0）改为 confidence masks 软边缘——置信度 0~1 直接映射为 alpha (0~255)，头发/边缘自然渐变柔化，定位为「快速预览」；新增方向自适应（对比人像/背景区平均置信度），避免再次抠反。
- **v1.3.3**：修正人像模式抠反问题——本环境 MediaPipe 类别掩码为 `0=人像、非0=背景`，前景判定由 `> 0` 改为 `=== 0`，人像被正确保留、背景被去除。
- **v1.3.2**：修复「切换通用/人像模式会自动抠图」；人像模式 delegate 改为 CPU 优先（避免 Safari/老旧设备的 GPU delegate 输出全透明、无成品），进度条加分段反馈，新增「未检测到人像」兜底提示。
- **v1.3.1**：修复人像模式 `MPMask` 报错（改用 `getAsUint8Array()`）。
- **v1.3.0**：新增「人像模式」接入 MediaPipe Selfie Segmentation。

## 本地预览（可选，仅用于开发查看效果）

由于浏览器对 `file://` 下的 ES Module 有 CORS 限制，请用一个静态服务器打开，而**不要直接双击**：

```bash
# 进入项目目录后，任选其一：
python3 -m http.server 8000        # 多数 Mac 可用（需装了 Python 3）
python -m SimpleHTTPServer 8000    # 系统自带 Python 2 的 Mac 可用
```

然后浏览器访问 `http://localhost:8000/`。

> 部署到 GitHub Pages 不必本地预览，直接提交即可，构建托管全在 GitHub 侧。

## 部署到 GitHub Pages（Deploy from branch）

适合**无需修改 Pages 设置**的静态托管方式。

1. 在 GitHub 网页新建空仓库（如 `cutout-web`），**公开**。
2. 打开仓库 **Settings → Pages**：
   - Source 选 **`Deploy from branch`**
   - Branch 选 **`main`**，文件夹 **`/ (root)`**
   - 保存
3. 把本仓库的四个文件（`index.html` / `style.css` / `app.js` / `README.md`）放到仓库**根目录**，提交并推送。
4. 约 1 分钟后访问 `https://<用户名>.github.io/<仓库名>/`。
   首次打开会联网从 CDN 加载抠图库、下载约 40MB 模型，稍慢，之后浏览器缓存。

## 后续更新（固定动作）

1. 拿到新的部署包（如 `cutout-deploy.tar.gz`），解压得到 `index.html` / `style.css` / `app.js` / `README.md`。
2. 拷贝覆盖到你本地仓库根目录（注意是根目录，不是子目录）。
3. 提交并推送：

```bash
cd /path/to/cutout-web
git add -A
git commit -m "更新到 vX.Y.Z"
git push
```

4. 等约 1 分钟，浏览器**强制刷新**（Cmd+Shift+R）确认页脚版本号与预期一致。

> 远程仓库的 Pages 设置只需配置一次，之后每次 push 自动重新部署，无需再动。
